# カード量産の作業指示（分野担当のエージェント向け）

院内のリハ職（PT/OT/ST）向けアプリ「リハに活かす薬剤ナビ」の薬効群カードを作る。見本3枚（β遮断薬・抗凝固薬・SU薬）が完成しており、これと同じ品質・書き方・構造でそろえる。

## まず読むもの

- `tools/seed_content.py`：見本3群の内容。**書き方・粒度・項目の埋め方はこれに合わせる**（ファイル末尾の `_G[...].update(...)` と `DRUGS` が確定版）
- `public/figures.js`：見本の図と共通部品（`window.FIG`）
- `tools/content/tags.py`：使ってよいリスクタグの ID 一覧（これ以外の ID は使わない）
- `設計メモ.md`：方針

## 作るファイル（自分の担当分だけ。ほかのファイルは編集しない）

1. `tools/content/<担当キー>.py`：`GROUPS`・`DRUGS`・`QUIZZES` の3つのリスト。列名（辞書のキー）は seed_content.py と同じ
2. `public/figures-<担当キー>.js`：担当カードの図

## 内容のルール（厳守）

- **数値・副作用・警告は、実際に開いて確認した添付文書だけ**を根拠にする。記憶で埋めない。推測で数値を作らない
- 添付文書の確認方法（PMDA は直接開けない）：
  1. `https://www.kegg.jp/medicus-bin/search_drug?display=med&search_keyword=<商品名をURLエンコード>` で japic_code を調べる
  2. `https://www.kegg.jp/medicus-bin/japic_med?japic_code=<コード>` を WebFetch し、改訂年月（第何版）、16.薬物動態の Tmax・t1/2 と条件、排泄、警告、11.1 重大な副作用、リハに関係するその他の副作用を本文どおり抜き出させる
- ガイドラインなどを使う場合も、実際に本文を確認できたものだけを出典にする
- 確認できなかったことは**画面に出る列には書かない**。必要なら「作成メモ」（画面に出ない）に「○○は出典未確認」と書く
- 用量の調整、薬の中止・変更、特定の患者への推奨は書かない。判断が必要な場面は「医師・薬剤師に確認」「報告」と書く
- 「報告の目安」の数値の中止基準は書かない（院内基準・安全管理ガイドライン第2版に従う、と見本どおり書く）
- 場面クイズは架空の人物（年代は10歳刻み・性別・病名の大分類まで、「（架空）」と明記）。各群1問。正解は「確認して報告・相談」系の行動にし、誤答もありがちな行動にする
- 文体は見本どおり：短い文、専門用語はかみくだく、太字は `**…**`、1項目1メッセージ
- 「リハで見るポイント」は3〜4項目、`見出し｜本文` の形。リハの場面（起立・歩行・運動負荷・移乗・ADL・嚥下・転倒）に必ずつなげる
- 個別薬は1群あたり代表2〜4剤。`Tmax（図用・時間）`・`半減期（図用・時間）` は添付文書の数値（時間単位）。図にしても意味がない薬（効果が血中濃度と対応しない、半減期が極端に長い、注射の持続投与など）は空欄にし、群の「時間_導入」でその理由を一言書く
- 半減期が長い群は「図の表示時間」を 48・72 などに変える
- 「出典」は1行1件：`<商品名> 添付文書 <YYYY年M月改訂（第N版）> https://www.kegg.jp/medicus-bin/japic_med?japic_code=<コード>`
- 「検査値リンク」は検査値アプリの項目名で、`表示名｜検索語`。使える検索語の例：PT-INR、PLT、Hb、WBC、eGFR、Cr、BUN、K、Na、Ca、血糖、HbA1c、BNP、CK、AST・ALT、CRP、Alb、TSH
- 「状態」は "下書き"。「群ID」「薬ID」「問題ID」は半角英小文字・数字・ハイフン、ほかの分野と重ならない名前（担当キーを先頭に付けると安全。例：`cv-ccb`）
- 「分野ID」：cv 循環器 / at 抗血栓 / dm 糖尿病 / cns 中枢神経 / pain 鎮痛・ステロイド / onc 抗がん剤 / imm 免疫抑制薬 / abx 抗菌薬

## 図のルール（品質を最優先）

ファイルの形（このとおりに書く。`F.<図ID> = {` は行頭に置く。ビルドがこの形で図IDを見つける）：

```js
// <分野名>の薬効の模式図（院内作成）
(function () {
  "use strict";
  var F = window.FIGURES, H = window.FIG;
  var rect = H.rect, text = H.text, pill = H.pill, arrow = H.arrow, head = H.head, tbar = H.tbar, inhibit = H.inhibit, result = H.result, svg = H.svg;

  F.cv_ccb = {
    alt: "（図の内容を文章で。読み上げ用）",
    svg: svg(300, /* 部品を + でつなぐ */ "")
  };
})();
```

- 図ID は半角英小文字・数字・アンダースコア（例 `cv_ccb`）。群の「図ID」列と一致させる
- viewBox は幅 360 固定（`svg(高さ, 中身)`）。文字は 13 以上（補足の小さい文字でも 12.5 以上）
- 色はトークンだけ：薬 `var(--drug)`／体の変化 `var(--body)`／促進の矢印 `var(--promote)`／抑制 `var(--inhibit)`（⊣ は `inhibit()`+`tbar()`）／中立の箱 `var(--surface-2)`+`var(--neutral)`／文字 `var(--ink)` `var(--ink-2)` `var(--ink-3)`。16進の色を直接書かない（ダークモードが崩れる）
- 1枚1メッセージ：「薬がどこに作用し → 体に何が起き → （必要なら）リハで何が問題になるか」。受容体・臓器・経路は薬理学的に正確に。迷う箇所は単純化し、不確かな経路は描かない
- **重なり厳禁**：文字と文字、文字と線、箱と箱が重ならないよう座標を計算する。日本語1文字の幅はおよそ font-size と同じ、英数字は約0.6倍で見積もる。箱の中の文字は左右に 8 以上の余白
- 線の端は箱の縁にきっちり接する。⊣ の棒は線の終点の位置に置く
- 見本の F.beta / F.anticoag / F.su の座標の取り方・部品の使い方を手本にする
- 図を作ったら、Node でファイルを読み込んで実行し（`window` を用意して評価し、`F.<id>.svg` が文字列として作れるか）、構文エラーがないことを確かめる

## 最後に返すもの

- 作ったファイル名
- 群ごとに：群ID・薬効群名・個別薬（薬ID）・図ID・問題ID
- 添付文書で確認した薬と改訂年月の一覧
- 確認できなかったこと（作成メモに書いた内容）
- 図で自信がない箇所があれば、その座標と理由
