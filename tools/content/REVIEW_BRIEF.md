# 内容精査の作業指示（専門家レビュー担当のエージェント向け）

院内のリハ職（PT/OT/ST、新人〜若手中心）向けアプリ「リハに活かす薬剤ナビ」の内容を、指定された立場から精査する。**ファイルは一切編集しない**（指摘を返すだけ。反映は取りまとめ側が行う）。

## 読むもの

- `設計メモ.md`：方針（とくに「表示の範囲」：用量・中止・変更の提案や特定患者への推奨は書かない。数値の中止基準は院内基準・安全管理GL第2版に従う、と書く方針）
- `public/data.js`：アプリに表示される全データ（31群・個別薬81剤・場面クイズ31問）。正本 Excel から自動生成したもの
- `public/figures.js`・`public/figures-*.js`：薬効の模式図（SVG を文字列で組み立てている）
- `public/app.js`：画面の文言（ホーム・カード・クイズ・注意書き）

## 精査のルール

- 事実（数値・副作用・作用機序・ガイドラインの記載）について「誤り」と指摘する場合は、**実際に開いて確認した一次情報の URL** を添える。添付文書は `https://www.kegg.jp/medicus-bin/search_drug?display=med&search_keyword=<商品名>` で japic_code を調べ、`https://www.kegg.jp/medicus-bin/japic_med?japic_code=<コード>` を WebFetch して確認する（PMDA は直接開けない）。確認できないものは「要確認」として出し、断定しない
- 記憶だけを根拠に新しい数値・事実を足す提案はしない
- 用量の調整・中止・変更の推奨にあたる表現、特定の患者への推奨に読める表現があれば指摘する
- 対象は内容（文章・数値・タグ・クイズ・図の医学的正確さと分かりやすさ）。見た目の好みは対象外
- 指摘は重要なものから最大 20 件。細かい言い回しの好みより、誤り・危険・誤解を招く表現・臨床で役に立たない箇所を優先する

## 返す形式（この形式で、日本語で）

指摘ごとに次の行をそろえる：

```
### <通し番号>. [重大|改善] <群IDまたは問題IDまたは図ID> / <項目>
- 現在：<該当箇所の文言（短く引用）>
- 提案：<差し替える文言。そのまま使える完成文で。削除なら「削除」>
- 理由：<なぜか。立場からの視点>
- 根拠：<確認した URL と該当箇所。なければ「一般的な臨床の観点（出典なし）」>
```

項目名は正本の列名を使う：リハで見るポイント／介入前の確認／報告の目安／流れ_薬／流れ_体の変化／流れ_リハ／薬効の仕組み／時間_導入／時間_ピーク付近／時間_その後／時間_時間に関係なく／主な副作用／検査値リンク／リスクタグ／代表薬／（個別薬は）Tmax（表示）・半減期（表示）・作用持続・排泄経路・メモ／（クイズは）場面・問い・選択肢1〜4・正解番号・解説／（図は）図ID と該当する文字。

最後に「全体所見」を3〜5行で書く。
